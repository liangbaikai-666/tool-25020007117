# 课程练习解答

## 1. 调试合并排序
- **Bug**：`merge` 函数的 `else` 分支中错误使用了索引 `i`，写成了 `append result, right[i]`，且未正确递增 `j`（虽然 `j = j + 1` 有写，但取的是 `right[i]`）。
- **修复**：将 `right[i]` 改为 `right[j]`。
- **调试**：在 `merge` 内设断点，单步执行会发现当走 `else` 分支时，错误地将 `left` 数组的数据（或越界值）加入结果，导致排序错乱。

  ## 4. strace / dtruss
  - 追踪 `ls -l`：运行 `strace ls -l`。
  - **系统调用**：主要包含 `execve`（加载程序）、`openat`/`fstat`（读取目录/文件属性）、`write`（输出结果到终端）、`close` 等。

  ## 5. LLM 辅助调试
  将编译器产生的冗长错误信息（如 C++ 模板实例化失败、Rust 生命周期错误）或 ASan 的完整输出复制给 LLM，要求其解释错误原因并给出修复代码。

  ## 6. perf stat
  - 命令：`perf stat <program>`
  - **计数器含义**：
  - `cycles`：CPU 时钟周期数。
  - `instructions`：执行的指令总数。
  - `cache-misses`：CPU 缓存未命中次数。
  - `branch-misses`：分支预测失败次数。

  ## 7. perf record (`slow.c`)
  - **编译**：`gcc -g -O2 slow.c -o slow -lm`
  - **记录**：`perf record -g ./slow`
  - **报告**：`perf report` 可看到 `slow_computation` 函数占用绝大部分时间。
  - **火焰图**：使用 `perf script | stackcollapse-perf.pl | flamegraph.pl > flame.svg` 生成交互式火焰图。

  ## 8. hyperfine 基准测试
  用于对比两个命令的性能，例如对比 `grep` 和 `ripgrep`：bash

  hyperfine 'grep -R "pattern" .' 'rg "pattern" .'9. htop / taskset

  - 命令：`taskset --cpu-list 0,2 stress -c 3`
  - **为何不用三颗 CPU**：`--cpu-list 0,2` 仅允许进程使用 CPU 0 和 CPU 2（共 2 个核心）。即使 `stress -c 3` 请求创建 3 个线程，它们也只能在被绑定的 2 个核心上运行，无法利用第三颗 CPU。

  ## 10. 端口占用排查
  - **启动服务**：`python -m http.server 4444`
  - **查找进程**：`ss -tlnp | grep 4444`（记下 PID）
  - **终止进程**：`kill <PID>`
