## 1. Git 提交大文件：将文件从完整提交历史删除

测试流程：

bash

```
# 初始化仓库
mkdir git_bigfile_demo && cd git_bigfile_demo
git init

# 创建普通文件 + 一个大测试文件
echo "normal content" > readme.txt
dd if=/dev/urandom of=bigfile.bin bs=1M count=5

# 提交两轮，大文件进入git历史
git add readme.txt bigfile.bin
git commit -m "add readme and bigfile"
echo "update readme" >> readme.txt
git add readme.txt
git commit -m "update readme"
```

彻底从**全部历史**删除文件

1. `git filter-branch`

bash

```
git filter-branch --force --index-filter "git rm --cached --ignore-unmatch bigfile.bin" --prune-empty --tag-name-filter cat -- --all
```

2.`git filter-repo`

bash

```
git filter-repo --path bigfile.bin --invert-paths
```

清理回收空间

bash

```
git reflog expire --expire=now --all
git gc --prune=now --aggressive
```

> 关键点：普通 `git rm bigfile.bin && git commit` **只能删除当前工作区，历史提交依然保存该大文件**。
>
> 

## 2. git stash 实验：修改文件，暂存、查看、恢复



bash

```
# 克隆任意仓库示例
git clone https://github.com/octocat/Hello-World.git
cd Hello-World

# 修改已有文件
echo "some local change" > README

# 工作区有改动，但不想立刻提交，使用stash暂存
git stash

# 此时运行 git status，工作区变回干净，修改被存进stash栈
git status

# 查看所有stash条目
git stash list
git log --all --oneline

# 恢复最近一次stash，把改动放回工作区
git stash pop
```

- `git stash`：把未提交的工作区 / 暂存区改动保存到隐藏栈，清空工作目录。
- `git stash list`：列出所有暂存记录。
- `git stash pop`：取出栈顶的 stash 并应用，应用后删除该 stash 记录。



## 3. Git 别名配置～/.gitconfig

需求：执行 `git graph` 等价于 `git log --all --graph --decorate --oneline`

### 1命令行直接配置

bash

```
git config --global alias.graph "log --all --graph --decorate --oneline"
```

测试运行：

bash

```
git graph
```

2：手动编辑 `~/.gitconfig`

打开文件，在 `[alias]` 块加入：

ini

```
[alias]
    graph = log --all --graph --decorate --oneline
```

保存后，终端执行 `git graph` 生效。

> `--global` 代表对本机全部 git 仓库生效；不加 global 仅对当前仓库生效。
>
> 

## 4. 全局 .gitignore 配置～/.gitignore_global

设置全局忽略规则，所有仓库统一忽略操作系统、编辑器临时文件。

bash

```
# 设置git全局忽略文件路径
git config --global core.excludesfile ~/.gitignore_global
```

编辑 `~/.gitignore_global`，写入忽略内容：

plaintext

```
# macOS
.DS_Store
.AppleDouble

# VSCode
.vscode/
*.swp
*.swo

# windows
Thumbs.db
```

> 注意：`git config` 只告诉 git 去哪里找文件，**文件需要自己手动创建编写**，配置命令不会自动生成该文件。
>
> 

## 5. GitHub 仓库 Fork + Pull Request（PR）练习

> 实操步骤：
>
> 

1. 在 GitHub 找一个公开的小型开源仓库
2. 点击页面右上角 `Fork`，复制一份到自己账号下
3. `git clone` 克隆你 fork 之后的仓库到本地
4. 修改文件，修复拼写错误或者小改进
5. `git add`、`git commit`、`git push` 推送到你自己 fork 的远程
6. GitHub 网页端会出现 “Compare & pull request” 按钮，打开，填写修改说明，提交 PR 给原项目。

> 练习提示：只提交真实有用的修改，不要提交无意义占位内容。找不到可以修改点可以跳过本练习。
>
> 

## 6. 模拟合并冲突完整实验

### 完整复制运行脚本

bash

```
# 创建实验仓库
mkdir git_merge_conflict && cd git_merge_conflict
git init

# 创建recipe.txt初始内容
cat > recipe.txt <<EOF
配方：
1 杯糖
少许盐
EOF

git add recipe.txt
git commit -m "初始配方提交"

# 创建两个分支 salty sweet
git branch salty
git branch sweet

# salty分支：修改同一行
git checkout salty
sed -i '' 's/1 杯糖/1 杯盐/' recipe.txt
git add recipe.txt
git commit -m "salty：糖改为盐"

# sweet分支：修改同一行
git checkout master
git checkout sweet
sed -i '' 's/1 杯糖/2 杯糖/' recipe.txt
git add recipe.txt
git commit -m "sweet：增加糖的量"

# 切回master，依次合并两个分支
git checkout master
git merge salty
git merge sweet
```

执行 `git merge sweet` 会报 **合并冲突**，`recipe.txt` 内容变成：

plaintext

```
配方：
<<<<<<< HEAD
1 杯盐
=======
2 杯糖
>>>>>>> sweet
少许盐
```

冲突标记含义：

- `<<<<<<< HEAD`：当前分支 (master) 的内容
- `=======`：分割线
- `>>>>>>> sweet`：待合并进来分支的内容

### 解决冲突流程

1. 打开 `recipe.txt`，手动删掉冲突标记，保留你想要的文本。
2. 将处理好的文件加入暂存区：

bash

```
git add recipe.txt
```

1. 完成合并提交

bash

```
git commit
# 新版本git也支持 git merge --continue
```

> 图形 / 终端合并工具：
>
> 

bash

```
git mergetool
```

### 可视化合并历史

bash

```
git log --graph --oneline
```

输出会看到分叉与两次合并的提交图。
